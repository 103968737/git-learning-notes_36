# 05 常见问题

按「启动 → 下载 → 推理 → 界面 → 性能」的顺序排查。每个问题都给出可直接执行的诊断命令。

## 1. 端口被占用

现象：`docker compose up -d` 报 `port is already allocated`，或 `bind: address already in use`。

```powershell
netstat -ano | findstr :11434
netstat -ano | findstr :3000
Get-Process -Id <PID>
```

解决办法：停掉占用进程，或在 `.env` 中改端口（`OLLAMA_PORT=11435`、`WEBUI_PORT=3001`），然后 `docker compose up -d` 重建。

## 2. 模型下载卡住 / 超时

现象：`ollama pull` 停在某个进度不动，或报 `dial tcp: i/o timeout`。

1. 先确认能访问模型仓库：`curl.exe -I https://registry.ollama.ai`。
2. 代理环境下，Docker 需要单独配置代理（Docker Desktop → Settings → Resources → Proxies），否则容器内不走系统代理。
3. 大模型中断后支持断点续传，直接重试 `ollama pull qwen2.5:7b` 即可。
4. 反复失败时换网络（手机热点）或换更小的模型验证链路是否通。

## 3. 重启后模型「消失」

`docker compose down` 不会删除数据卷；但 `docker compose down -v` 会。模型存在命名卷 `local-ai-ollama-models` 中：

```powershell
docker volume ls
docker compose exec ollama ollama list
```

如果确实误删，重新 `ollama pull` 即可。

## 4. GPU 没被使用

现象：回答很慢，日志里出现 `offloaded 0/29 layers to GPU` 或纯 CPU 推理。

```powershell
nvidia-smi                    # 显卡与显存是否可见
docker run --rm --gpus all nvidia/cuda:12.4.0-base-ubuntu22.04 nvidia-smi
```

检查项：

1. `docker-compose.yml` 里的 GPU 段是否已取消注释；
2. Docker Desktop → Settings → Resources → Advanced 是否启用了 GPU；
3. Windows 需要 WSL 2 与较新的 NVIDIA 驱动；
4. 集显/AMD 显卡：Ollama 对 Windows 上 AMD 的支持有限，大概率会回落到 CPU。

## 5. 显存不足（OOM / 崩溃）

现象：`CUDA out of memory`，或请求直接把容器打挂。

- 换更小的量化或更小的参数：`qwen2.5:14b` → `qwen2.5:7b`；
- `OLLAMA_NUM_PARALLEL=1`、`OLLAMA_KEEP_ALIVE=1m`，减少同时驻留；
- 降低上下文（`num_ctx=4096`）；
- 关闭其他占显存的程序（浏览器硬件加速、游戏、Stable Diffusion）。

## 6. 第一个请求特别慢

首次请求要把权重从磁盘读进显存，7B 模型通常 10～40 秒。之后靠 `OLLAMA_KEEP_ALIVE` 保持热加载。可在启动脚本里先发一个空请求预热。

## 7. WebUI 打不开或白屏

```powershell
docker compose ps
docker compose logs -f webui
```

- 首次启动要初始化数据库，等 1～2 分钟；
- 看到 `OLLAMA_BASE_URL` 连接失败时，确认 `ollama` 服务健康（`docker compose ps` 中为 healthy）；
- 端口冲突见第 1 条；
- 浏览器缓存问题可强制刷新（Ctrl+F5）。

## 8. WSL 2 占用内存过高

Docker Desktop 使用 WSL 2 时，虚拟机会持续占用内存。在 `C:\Users\<用户名>\.wslconfig` 中限制：

```ini
[wsl2]
memory=8GB
processors=4
swap=2GB
```

保存后执行 `wsl --shutdown`，再重启 Docker Desktop。

## 9. 磁盘空间不足

```powershell
docker system df
docker image prune -f
docker builder prune -f
```

模型文件在 `docker volume inspect local-ai-ollama-models` 显示的目录中，删除不用的模型用 `ollama rm <model>`。

## 10. 中文输出乱码

- PowerShell 7 默认 UTF-8，一般无需处理；
- Windows PowerShell 5.1 可先执行 `chcp 65001`；
- 脚本读取/写入文件时显式使用 UTF-8：`Get-Content -Encoding utf8`、`Out-File -Encoding utf8`；
- Python 脚本请确保源码文件为 UTF-8，并在输出时 `sys.stdout.reconfigure(encoding="utf-8")`。

## 11. Linux 下 docker 权限不足

现象：`permission denied while trying to connect to the Docker daemon socket`。

```bash
sudo usermod -aG docker $USER
newgrp docker     # 或重新登录
```

## 12. 模型回答质量差

先排除环境问题，再考虑模型本身：

1. 是否用了过小的量化（Q2/Q3）→ 换 Q4_K_M 以上；
2. 是否上下文太短导致答案被截断 → 检查 `done_reason` 是否为 `length`；
3. 提示词是否缺少角色与格式约束 → 补 system prompt；
4. 换更大参数或更适合中文的模型做对比。

## 13. 执行脚本提示 running scripts is disabled

Windows 默认的脚本执行策略可能禁止运行 `.ps1`：

```
无法加载文件 ...\check-env.ps1，因为在此系统上禁止运行脚本。
```

两种解决方式（任选其一）：

```powershell
# 方式一：只在当前 PowerShell 窗口生效，最安全
Set-ExecutionPolicy -Scope Process Bypass -Force
.\scripts\check-env.ps1

# 方式二：直接以绕过策略的方式调用
powershell -ExecutionPolicy Bypass -File .\scripts\check-env.ps1
```

不建议使用 `Set-ExecutionPolicy Unrestricted` 全局放开，风险更高。
